# ns-capability-drift

Capability-doc drift + coverage audit against the Ultron codebase. Night-shift process **P2**; also runnable on demand.

## Invocation
Invoked by the `night-shift-fanout` workflow as `/ns-capability-drift for LOCAL=<date>`. Runnable solo: `/ns-capability-drift` (defaults LOCAL to today; solo = the on-demand behavior in "Solo run" below).

## Artifact contract (PRIMARY OUTPUT)
Resolve `LOCAL` (from the invocation, else `TZ=America/Denver date +%Y-%m-%d`). Write `00 Inbox/<LOCAL>-ns/P2.md` with frontmatter `process: P2`, `status: complete|failed`, an optional `needs_kyle:` list, and a body = the report-section text — this artifact is the source of truth. Do NOT commit/push; honor Confidential/ strict mode.

The body MUST include an **"Applied overnight — review the diff"** section (so Kyle reviews a diff + summary, not a proposal list — he approves at `/push`): (a) **per-doc T1/T2 edits applied**, each with its citing commit (`EJA edit → capability-X.md, per <short-sha>`); (b) **T3 drafts** created (full-draft vs skeleton, links); (c) **T4 surfaced** items (→ these also go in `needs_kyle:`). The night-shift FINALIZE lifts this into the `## Overnight` digest.

**STRUCTURED RETURN (2026-07-08 reliability #3):** in addition to the prose artifact, RETURN `{ appliedT2: [{doc, claim, commit, cite}], summary }` — one entry per T2 content edit auto-applied this run (empty array if none; `summary` = the report-section text as a convenience). The workflow's Verify phase consumes `appliedT2` to run the independent author≠verifier re-check (see the T2 gate). Getting this list right is load-bearing: an applied T2 edit omitted from `appliedT2` escapes verification.

## Procedure

**Findings are candidates, not facts** (CLAUDE.md § Analysis approach → verify-before-assert): PASS A's flagged drifts and PASS B's coverage gaps are hypotheses. Re-ground each against the live worktree at the point of writing — cite the current commit + `path:line` for every applied edit; a claim that doesn't re-verify downgrades to T4 (surface, don't write).

**Never infer a domain term's meaning** (verify-before-assert, check 1): when a capability doc, a new subsystem, or a cited code path uses a load-bearing acronym/term (e.g. a class or config key) **not** in `03 Resources/glossary.md`, do NOT write an inferred expansion into the doc from surface cues (the DPfA-mislabeled-as-NextWave class of miss). Surface it in the P2 artifact's `needs_kyle:` as a **proposed glossary addition** (term + best-effort scope + "meaning unconfirmed") for Kyle to confirm; leave the doc's wording term-neutral until then. Never auto-add to the glossary.

PROCESS 2 — Capability docs: drift (update existing) + coverage (expand for new subsystems). TWO passes.
- PASS A — update existing (**apply-staged**, 2026-07-02): For each `03 Resources/ultron/capabilities/capability-*.md`, read its `last_synced` + cited code paths (backend/… frontend/… infrastructure/…). **CITED-PATH EXTRACTION (2026-07-07 — run-38 false positive; applies to PASS B's covered set too):** a doc mention counts as a cited path ONLY if it names a specific subsystem or file — at least one segment beyond the SOURCE ROOTS, which are (explicit list, not inferred): `frontend/src`, `backend`, `infrastructure`, and any bare repo top-level dir. So `frontend/src/shared/lib/pendo/` and `backend/<Project>/…/Foo.cs` are citations; bare `frontend/src` / `backend` / `infrastructure` prose mentions are NOT (as git-log pathspecs they match essentially every commit, so the doc flags drifted every night). Breadth test when unsure: if the pathspec would match a large share of the repo's commits, it's prose, not a citation. Known perpetual re-flag sources that fail this test even though they clear the segment rule — treat as non-citations: `infrastructure/terraform/`, `infrastructure/aks/nonproduction/zones/**`, `infrastructure/tilt/**` (all high-churn infra dirs — ~25 infra-churn commits since 2026-07-03; the aks/tilt paths hit the credential-check doc's git gate on 2026-07-16 and re-flag every night). Strip `:line` anchors before using a citation as a pathspec (`Foo.cs:214` → `Foo.cs`; the verbatim form matches nothing — a silent false negative). A rootless fragment (`Slices/EdjUserInfo/`) is a citation only if it resolves to exactly ONE full path in the worktree — use the resolved path; unresolvable/ambiguous → not a citation. If a doc's ONLY code references are non-citations, treat it as citing nothing: skip the git gate, note "no discriminating citations" in the artifact, and **surface it ONCE as T4 ("doc has no discriminating citations — add code anchors")** so it doesn't silently exit the audit forever. This definition governs PASS B's covered-set union as well — one bare `frontend/src` mention must not blanket the whole frontend tree as "covered" and mask the coverage gaps PASS B exists to find. In ~/code/worktrees/main, check if any cited path changed since: `git log --since="<last_synced>" --name-only -- <cited paths>`. No change → skip the doc. For drifted docs (CAP ~8 most-drifted/night; note deferred), verify each flagged citation in the worktree and **classify each drift into a tier** (design: `99 Meta/specs/2026-07-02-capability-doc-autoupdate-design.md`):
    - **T1 — mechanical:** a cited `path:line` moved/renamed with a single unambiguous grep match, or a renamed symbol with a single clear replacement, or a dead link. **AUTO-APPLY.**
    - **T2 — content drift with a clear code basis:** a documented behavior/method/flow that *provably* changed per a specific commit (the doc's claim no longer matches the code). **AUTO-APPLY, staged, ONLY through the verify gate:** the edit must (1) **cite** the exact commit + `path:line` that justifies it, and (2) **pass an INDEPENDENT re-verify** by a fresh critic that is NOT the authoring subagent. **WHERE the critic runs (2026-07-08 reliability #3 fix):** when dispatched by the night shift, P2 has no Task tool and CANNOT spawn a verifier — so P2 does NOT self-verify. Instead it **records every applied T2 edit in its structured return** (`appliedT2: [{doc, claim, commit, cite}]`, per the artifact contract) and the **workflow's Verify phase** spawns one independent critic per edit (author≠verifier, enforced by the workflow). When run **solo** (interactive `/ns-capability-drift`, where the Task tool IS available), P2 spawns its own fresh verifier subagent as before. A **REFUTED** verdict → the critic **REVERTS** the staged edit (uncommitted, so revert = restore prior text) and it surfaces loudly; **uncertain → treat as refuted** (never leave an unverified content edit in the knowledge layer). Pass → the edit stays. **Fail / uncertain → the doc claim DOWNGRADES to T4** (surface, do NOT keep the write).
    - **T4 — interpretive / structural** (doc reorg, a semantic claim needing judgment): **DO NOT edit; report under "Needs Kyle."**
    - Bump that doc's `last_synced: <LOCAL>` ONLY if EVERY drift in it resolved (all T1+T2 applied+verified, zero T4 residue) — a doc with any surfaced T4 re-surfaces next run.
    - Spot-check before trusting (agents make systematic errors — scope-limited greps, wrong symbol names). Up to ~6 parallel subagents for per-doc verification + the T2 author-vs-verifier split.
- PASS A-anchor — WEEKLY line-anchor refresh (Sundays, `+%u`==7 — mirrors PASS B's full-tree cadence). PASS A's git-log gate skips any doc whose cited paths did NOT change since `last_synced` — right for *content* drift, but it lets **pure line-number rot** accumulate in two cases the nightly pass never revisits: (i) docs deferred past the ~8/night cap, and (ii) anchors into large/generated regions (the AnnuitySummaryDocument 4352-line table, cred-check offsets) where a `path:line` can't resolve to a single grep match, so T1 never fixes it and it parks as T4. On the Sunday full-tree run, re-verify the `file:line` anchors of **EVERY** capability doc against the current worktree (not just the git-drifted set): for each cited `path:line`, grep the anchored symbol/text at that path.
    - Exact match at the cited line → no-op.
    - **Single unambiguous match at a DIFFERENT line → T1 auto-apply** (correct the line number only).
    - Multiple matches / big-table region / no match → **T4 surface** (report the current best-effort line + "anchor ambiguous — verify"); never guess a line.
  Anchor-number-only — it does NOT touch prose (that's PASS A's content-drift job) and does NOT bump `last_synced` on its own (defer to PASS A's rule). Same verify-before-write discipline: a correction that can't resolve to exactly one match downgrades to T4 (uncertainty never writes). Fold the applied/surfaced counts into the P2 artifact's "Applied overnight" section.
- PASS B — expand coverage (catch undocumented subsystems; P2 is otherwise doc-anchored and blind to systems no doc cites): build the COVERED SET = union of all code paths cited across every capability doc. Then find code NOT in the covered set:
    - **COVERED-SET CONSTRUCTION — five rules, ratified by Kyle 2026-08-02** (from the `ultron-capability-coverage-crawl` audit; measurements are from that run against `7b1886ae2f`):
        1. **Coverage flows upward only.** A subsystem `S` is covered iff some citation resolves to a path *at or beneath* `S`. A citation to an **ancestor** of `S` never covers `S`. Without this, one citation to `frontend/src/features/annuity-adviser/` marked **324 files** documented on the strength of a section header — which is how the ~101-file disclosures subsystem stayed invisible until 2026-08-01.
        2. **Breadth alone is not the test — structure is.** A citation resolving to ≥150 files is a *candidate* for citation debt, not a finding. Apply the structural test first: **if the citing doc contains ≥3 citations resolving strictly beneath that path, it is a section/table header introducing an anchored enumeration — an index reference, not debt.** Report only the remainder. (Of 44 broad sites: **29 index references, 15 real debt.** Pure breadth would report all 44 — and writing a proper inventory table *creates* a new broad citation for its header row, so the naive rule penalises the very fix it demands.)
        3. **Two exemptions, declared in the doc rather than in the tool.** (a) A path named inside an **absence or contrast** claim is not a citation — reuse PASS A's negated-claim detector on the covered-set pass. (b) A tree the doc explicitly declares **pattern-covered** is covered (e.g. `capability-release-engineering.md` for `infrastructure/aks/**/zones/**`, `infrastructure/aks/production/zone/**`, `infrastructure/terraform/`, `infrastructure/tilt/`) — near-identical generated manifests where the generating rule is the information. **Without (a) and (b), 12 of the 15 remaining debt sites are false positives.** This supersedes the hard-coded infra exclusion list in PASS A's citation rule: the declaration now lives in the doc, not here.
        4. **Resolve a rootless token against its nearest enclosing path context.** Inventory tables write bare class/subdir names (`ApplicationProjectAnnuitySigningSlice`, `services/signing/`) because repeating the full path on 28 rows is unreadable; the extractor sees a bare token and credits nothing. Resolve each rootless token against the most recent resolvable path in the same section before falling back to a global suffix match. (**~1,250 of backend's 1,557 PROSE-ONLY files** — including inventories written specifically to fix blanketing. The docs are right; the tool cannot see them.)
        5. **Cited is not owned.** A path can appear as a size reference, a contrast, or an explicit disclaimer of ownership — none are coverage. Credit only where the surrounding text *describes* the subsystem. Approximation: a citation whose line carries an ownership disclaimer (`not owned`, `no capability doc`, `still a gap`, `needs its own page`) or which appears only inside a file-count parenthetical does not credit. (Measured on the crawl's **own** edits: a row reading "⚠ Not owned by any capability doc" marked read-aloud covered, and a five-number file-count sentence took `partners/edward-jones` from 285 uncovered to 2 while documenting nothing. Neither is a negation, so rule 3(a) does not catch them.)
        **Generator:** `.claude/skills/ns-capability-drift/extract.py` + `pertree.py` regenerate every coverage table. Re-run them so each audit **diffs against the prior baseline** instead of rebuilding the tool. Baseline: 2026-08-02, 13,604 tracked → 1,088 excluded → 12,516 in scope.
    - NIGHTLY: from the synced commit range (old→new HEAD), collect added paths (`git diff --diff-filter=A --name-only <old>..<new>`) + newly-created directories.
    - WEEKLY FULL-TREE AUDIT: when `TZ=America/Denver date +%u` == 7 (Sunday run), instead scan the WHOLE tree — enumerate subsystem-level dirs (partitions / slices / services / consumers / feature areas / third-party services) and diff against the covered set to catch PRE-EXISTING undocumented subsystems, not just new ones.
    - For each SUBSTANTIAL uncovered subsystem (a new partition/slice/service/consumer/feature area or third-party service — ignore trivial/test/generated/config paths): decide whether it belongs in an existing doc (→ enrichment note) or needs a NEW capability doc. Report all gaps under a "Coverage gaps / new subsystems" section.
    - For each gap needing a NEW doc (**T3**), generate a draft to `00 Inbox/<LOCAL>-capability-draft-<slug>.md`, staged (NEVER auto-placed in the capabilities dir — Kyle reviews + moves it in; keeps Pass A's `capability-*.md` glob clean):
        - **Clear scope + entry points → a FULL draft** (2026-07-02): frontmatter (name, `last_synced: <LOCAL>`, `status: draft`), scope, a code map + the key flows, and code anchors (file:line) — matching the capability-doc shape, fleshed out from the code, not just an outline. Same code-grounding discipline as T2 (claims tied to file:line; spot-verify before writing).
        - **Ambiguous scope → fall back to a SKELETON** (`status: draft-skeleton`): one-line scope + section outline + entry-point anchors only.
      CAP ~4 drafts/night; list any deferred.
- All edits (T1/T2) + drafts (T3 full/skeleton) stay UNCOMMITTED — the human gate is Kyle's `/push` after reviewing the diff. (Drafts live in `00 Inbox/`, not the capabilities dir, so Pass A's `capability-*.md` glob never picks them up.)

## Solo run
Same behavior, LOCAL defaults to today (`TZ=America/Denver date +%Y-%m-%d`). No diagnosis cache is involved (P2 consumes none). Still write the `00 Inbox/<LOCAL>-ns/P2.md` artifact; all edits and skeleton drafts stay uncommitted.
